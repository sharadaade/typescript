Start Here: How to Learn
Learn JavaScript behavior and TypeScript types together. JavaScript supplies the behavior that runs; TypeScript adds checks while you develop.

Language, runtime, and browser APIs

Definition: A language defines syntax and meaning. A runtime executes code. Browser APIs let code interact with the page.

An array and a function are JavaScript features. An interface is a TypeScript feature. document, localStorage, and click events are browser features. Node has different APIs, so browser examples cannot be pasted into every Node script.

When to use it: Use this distinction when an example says document is not defined or a type has no runtime value.

Example · independent snippet
// JavaScript behavior with a TypeScript annotation
const price: number = 200;
console.log(price * 2);
// Compiled JavaScript has no : number annotation.

Result explained: The printed result is 400. The type annotation does not perform multiplication; JavaScript does.

Common mistake
Installing TypeScript does not automatically add a browser DOM to Node.

Recommended study order

Definition: A learning path is an ordered sequence where later lessons build on earlier ones.

Start with JavaScript foundations, then TypeScript fundamentals, functions, data structures, narrowing, modules, advanced types, browser events, and practical projects. Skip advanced chapters temporarily if their prerequisites are unfamiliar.

When to use it: Follow the sidebar from top to bottom if you are new to both languages.

Common mistake
Mark complete only after you can explain and modify the example.

How to run examples

Definition: A snippet is a small independent example, rather than one part of a single giant program.

Use the TypeScript Playground for language examples or a local TypeScript project. DOM lessons need matching HTML in a browser. API lessons need a real server or mock response. Examples marked as errors are intentional demonstrations.

When to use it: Copy one snippet at a time, predict its output, and change one value or type.

Common mistake
Combining every snippet into one file creates duplicate names and unrelated errors.

Variables, Values & Data Types
Variables give names to values. Learn the runtime types before adding TypeScript annotations.

let, const, and var

Definition: let declares a reassignable block-scoped binding. const declares a block-scoped binding that cannot be reassigned. var is function-scoped.

Use const by default and let when the binding must change. A const object may still have mutable properties: const protects the binding, not the entire object. var has older scope rules and is usually avoided in new code.

When to use it: Store a booking ID with const and an accumulating total with let.

Example · independent snippet
const bookingId = 101;
let total = 0;
total += 250;
const user = { name: "Alice" };
user.name = "Bob";

Result explained: total becomes 250 and user.name becomes Bob. user itself still refers to the same object.

Common mistake
const does not mean deeply immutable.

Primitive values and objects

Definition: Primitives include string, number, boolean, bigint, symbol, undefined, and null. Objects include arrays, functions, and ordinary records.

A string stores text; a number stores a numeric value; a boolean stores true or false. undefined commonly means no value was supplied, while null often means intentionally empty. Objects group values under properties.

When to use it: Choose a value representation that reflects the data you need.

Example · independent snippet
const title = "Room 201";
const price = 1200;
const available = true;
const guest = null;
const rooms = [201, 202];
console.log(typeof title, typeof price, typeof rooms);

Result explained: The output types are string, number, and object. Arrays are objects at runtime.

Common mistake
typeof null is "object", a historical JavaScript quirk. Use value === null to check null.

Scope, Hoisting & Closures
Scope decides where a name is available. Closures let functions remember variables from their surrounding scope.

Block and function scope

Definition: A block is a region between braces. Block-scoped bindings are accessible within that block and its nested scopes.

let and const are block-scoped. A function has its own scope for parameters and local bindings. A nested function can read outer bindings, but code outside cannot read inner bindings.

When to use it: Keep temporary names local and avoid global name collisions.

Example · independent snippet
function calculate(): number {
  const base = 100;
  if (base > 0) { const fee = 10; return base + fee; }
  return base;
}
console.log(calculate());

Result explained: The result is 110. fee is accessible only within the if block.

Common mistake
Reading a block-local name outside its block causes an error.

Hoisting and the temporal dead zone

Definition: Hoisting describes how declarations are established before code executes. The temporal dead zone prevents access to let/const before initialization.

Function declarations can generally be called before their declaration in the same scope. let and const bindings exist but cannot be used before initialization. var can appear as undefined before assignment.

When to use it: Understand errors caused by declaration order.

Example · independent snippet
sayHello();
function sayHello(): void { console.log("Hello"); }
// console.log(total); // error before initialization
let total = 10;

Result explained: sayHello prints Hello. The commented access to total is invalid.

Common mistake
Do not assume all declarations are usable before the line where they appear.

Closures

Definition: A closure is a function together with access to its surrounding lexical environment.

A returned function can continue accessing an outer variable even after the outer call finishes. Each outer call creates separate state. This is used by event handlers, factories, and callbacks.

When to use it: Create private counters or remember configuration.

Example · independent snippet
function createCounter(): () => number {
  let count = 0;
  return () => ++count;
}
const next = createCounter();
console.log(next(), next());

Result explained: The results are 1 and 2 because both calls share the captured count binding.

Common mistake
A closure remembers a binding, not always a frozen copy of its original value.

Try it yourself

Create a counter that starts at 10 and increases by 2 on every call.

Show a possible solution 
function counter(start: number): () => number {
  let value = start;
  return () => value += 2;
}
const next = counter(10); // next(): 12, then 14

Operators, Equality & Conversion
Operators combine, compare, or transform values. JavaScript conversion rules still apply in TypeScript.

Arithmetic and assignment

Definition: Arithmetic operators compute values. Assignment operators update bindings.

+ adds numbers but also concatenates strings. -, *, /, %, and ** perform subtraction, multiplication, division, remainder, and exponentiation. += combines an operation with assignment.

When to use it: Calculate totals, percentages, and counters.

Example · independent snippet
console.log(10 + 5, 10 % 3, 2 ** 3);
console.log("10" + 5);
const parsed = Number("10");
console.log(parsed + 5);

Result explained: The outputs are 15, 1, 8; then "105"; then 15. Number performs an explicit runtime conversion.

Common mistake
A type assertion is not conversion. Number("bad") produces NaN.

Strict equality

Definition: === compares values without the coercion performed by ==. !== is strict inequality.

Prefer === and !== for predictable comparisons. Two separate objects compare unequal even when their properties are identical because identity is compared. NaN is not equal to itself; Number.isNaN checks it.

When to use it: Compare status values, IDs, and expected results.

Example · independent snippet
console.log(5 === 5); // true
const a = { id: 1 };
const b = { id: 1 };
console.log(a === b); // false
console.log(Number.isNaN(Number("bad"))); // true

Result explained: Objects a and b are different objects, so their identities differ.

Common mistake
=== does not deeply compare arrays or objects.

Logical, ternary, and nullish operators

Definition: && and || short-circuit; condition ? a : b chooses a branch; ?? supplies a fallback only for null or undefined.

Logical operators return one of their operands, not necessarily a boolean. ?? preserves valid 0, false, and empty strings. Optional chaining ?. stops property access when the preceding value is nullish.

When to use it: Choose defaults and access optional data safely.

Example · independent snippet
const count = 0;
console.log(count || 10, count ?? 10);
const user: { name?: string } | null = null;
function label(u: { name?: string } | null): string {
  return u?.name ?? "Guest";
}
console.log(label(user));

Result explained: The outputs are 10, 0, and Guest. || treats zero as falsy, while ?? does not.

Common mistake
Mixing ?? with && or || requires parentheses.

Try it yourself

Convert "1200" to a number, check that it is finite, and preserve a quantity of zero when supplying defaults.

Show a possible solution

console.log(Number.isFinite(price));
const quantity = 0;
console.log(quantity ?? 1);

Conditions & Control Flow
Control flow determines which statements execute and when.

if, else if, and else

Definition: An if statement executes a branch when its condition is truthy. else if tests another condition; else is the fallback.

Truthiness converts a value to a boolean-like decision. false, 0, -0, 0n, "", null, undefined, and NaN are falsy. Empty arrays and empty objects are truthy.

When to use it: Choose business-rule branches such as room availability.

Example · independent snippet
function classify(price: number): string {
  if (price < 0) return "invalid";
  else if (price === 0) return "free";
  else return "paid";
}
console.log(classify(0));

Result explained: The result is free because the second condition matches.

Common mistake
A truthiness check can hide a valid empty string or zero.

switch and fall-through

Definition: switch compares an expression with case values. Without a return or break, execution can continue into later cases.

Use switch when one value has several named states. break exits the switch; return exits the enclosing function. default handles otherwise unmatched values.

When to use it: Handle a booking status or menu action.

Example · independent snippet
function message(status: "pending" | "paid"): string {
  switch (status) {
    case "pending": return "Awaiting payment";
    case "paid": return "Confirmed";
  }
}

Result explained: Each status selects its matching returned message.

Common mistake
A missing break in a statement-style switch can run the next case unexpectedly.

Try it yourself

Write a function returning child for age below 18, adult for 18–59, and senior for 60 or above.

Show a possible solution

  if (age < 18) return "child";
  if (age < 60) return "adult";
  return "senior";
}

Functions, Arrows & Callbacks
Functions package reusable work. Callbacks let one function receive behavior from another.

Declaration, expression, and arrow

Definition: A function declaration names a function. A function expression creates a function as a value. An arrow is a shorter expression with lexical this.

Parameters are placeholders in the definition; arguments are values passed at a call. return sends a result to the caller and stops that invocation. A missing meaningful return generally produces undefined.

When to use it: Avoid repeating a calculation or validation rule.

Example · independent snippet
function add(a: number, b: number): number { return a + b; }
const multiply = function(a: number, b: number): number { return a * b; };
const double = (n: number): number => n * 2;
console.log(add(2, 3), multiply(2, 3), double(3));

Result explained: The results are 5, 6, and 6. These functions all return numbers.

Common mistake
An arrow with braces needs an explicit return for a result; n => { n * 2; } returns undefined.

Callbacks and higher-order functions

Definition: A callback is a function passed to another function. A higher-order function accepts or returns a function.

Functions are values, so you can store and pass them. TypeScript can describe the callback signature and infer its parameter types from context. A callback is not automatically asynchronous.

When to use it: Transform arrays, handle events, or customize a workflow.

Example · independent snippet
function apply(value: number, operation: (n: number) => number): number {
  return operation(value);
}
console.log(apply(5, n => n * 3));

Result explained: The result is 15. apply calls the callback with 5.

Common mistake
Passing handler() passes its return value; passing handler passes the function itself.

Pure functions and side effects

Definition: A pure function returns a result determined by its inputs without modifying outside state. A side effect changes or interacts with something outside the call.

Logging, updating the DOM, making a request, and mutating a shared object are side effects. Pure transformations are easier to test. Real apps need effects, but keeping calculation separate makes behavior easier to reason about.

When to use it: Separate pricing calculations from saving a booking.

Example · independent snippet
function withTax(price: number, rate: number): number {
  return price * (1 + rate);
}
console.log(withTax(100, 0.18));

Result explained: The calculation produces 118; console.log is a separate side effect.

Common mistake
Mutating an input array unexpectedly can affect other callers.

Try it yourself

Write apply twice: once with a callback that adds 10, then with one that halves its input.

Show a possible solution 
apply(20, n => n + 10); // 30
apply(20, n => n / 2); // 10

Objects, References & Copying
Objects group related data. Understanding object identity prevents accidental mutations.

Properties and methods

Definition: A property is a named value on an object. A method is a property whose value is a function.

Use dot notation for a known identifier and bracket notation for a computed key. Optional chaining can guard a nullish object, but it does not validate a property value.

When to use it: Represent rooms, customers, and configuration.

Example · independent snippet
const room = { number: 201, price: 1200, describe() { return `Room ${this.number}`; } };
console.log(room.price, room["number"], room.describe());

Result explained: The values are 1200, 201, and "Room 201".

Common mistake
A missing property can produce undefined. TypeScript rejects undeclared properties on precise object types.

Reference identity and shallow copies

Definition: Object assignment copies the reference value. A shallow copy creates a new outer object while reusing nested references.

JavaScript passes values; for objects, that value is a reference. Mutating the referenced object can therefore be visible to the caller. {...object} does not deeply clone every nested property.

When to use it: Copy a flat record before changing it.

Example · independent snippet
const original = { name: "Alice", address: { city: "Pune" } };
const copy = { ...original };
copy.name = "Bob";
copy.address.city = "Mumbai";
console.log(original.name, original.address.city);

Result explained: The result is Alice and Mumbai. The names are independent, but the address object is shared.

Common mistake
Calling this pass-by-reference is imprecise: the reference itself is passed by value.

Object.keys, values, and entries

Definition: Object.keys returns own enumerable string keys; values returns their values; entries returns [key, value] pairs.

These methods skip inherited properties and symbol keys. They make object traversal clearer than unguarded for-in when you only want the object’s own data.

When to use it: Display a settings dictionary.

Example · independent snippet
const prices: Record<string, number> = { single: 1000, double: 1800 };
for (const [kind, price] of Object.entries(prices)) {
  console.log(kind, price);
}

Result explained: The loop visits the single and double entries.

Common mistake
Object.keys typically returns string[], not a guarantee of exact keyof keys for every runtime object.

Try it yourself

Create a copy that changes a nested city without modifying the original object.

Show a possible solution

Destructuring, Spread & Rest
Use concise syntax to unpack, copy, combine, or collect values.

Destructuring and defaults

Definition: Destructuring extracts values from an object or array into bindings. Defaults apply when the extracted value is undefined.

Object destructuring matches names; array destructuring matches positions. You can rename an object property in the new binding. A default does not replace null.

When to use it: Read request options or tuple results.

Example · independent snippet
const room = { number: 201, price: 1000 };
const { number: roomNumber, price } = room;
const [first, second = 0] = [10];
console.log(roomNumber, price, first, second);

Result explained: The values are 201, 1000, 10, and 0.

Common mistake
Destructuring a null or undefined object throws unless you guard or provide an object fallback.

Spread syntax

Definition: Spread expands iterable elements or object properties into a new container or call.

[...items] creates an array copy; {...record} copies own enumerable properties. Later object properties override earlier properties with the same name. Copies are shallow.

When to use it: Merge configuration or append items without changing the old array.

Example · independent snippet
const defaults = { theme: "dark", size: 14 };
const config = { ...defaults, size: 16 };
const numbers = [1, 2];
const extended = [...numbers, 3];
console.log(config.size, extended);

Result explained: size becomes 16; extended contains 1, 2, 3.

Common mistake
Object spread is not a deep copy, and spreading an object into an array needs an iterable object.

Rest syntax

Definition: Rest collects remaining arguments or properties into one binding.

The same ... symbol performs collection in a declaration and expansion in an expression. A rest parameter is last and receives an array. Object rest excludes the already-extracted properties from the new outer object.

When to use it: Accept multiple prices or separate an ID from editable fields.

Example · independent snippet
function total(...prices: number[]): number {
  return prices.reduce((sum, price) => sum + price, 0);
}
const { id, ...editable } = { id: 1, name: "Alice", email: "a@example.com" };
console.log(total(100, 200), editable.name);

Result explained: The total is 300; editable contains name and email.

Common mistake
A rest parameter must be last. Rest does not remove fields from the original object.

Merge two room lists and override a default currency with INR.

Loops: for, while, for-in & for-of
A loop repeats a block of work. Pick a loop based on whether you need a counter, a condition, keys, or values.

for

Definition: for repeats using an initializer, a condition checked before each iteration, and an update step.

The initializer usually creates a counter. The body runs while the condition is true. The update runs after the body. This gives explicit control over indexes and steps.

When to use it: Visit indexes, count attempts, or step through every second item.

Example · independent snippet
for (let index = 0; index < 3; index++) {
  console.log(index);
}

Result explained: It prints 0, 1, and 2. The condition becomes false at 3.

Common mistake
Using <= array.length accesses one index past the end.

while and do-while

Definition: while checks its condition before the body. do-while checks after the body, so it executes at least once.

Update the state that controls the loop so it can finish. A while loop may run zero times. do-while is useful when one attempt is always required before deciding whether to continue.

When to use it: Repeat until a condition changes.

Example · independent snippet
let remaining = 3;
while (remaining > 0) { console.log(remaining); remaining--; }
let attempts = 0;
do { attempts++; } while (attempts < 1);

Result explained: The while prints 3, 2, 1; the do-while executes once.

Common mistake
A condition that never changes can create an infinite loop.

for-in

Definition: for-in visits enumerable string property keys, including inherited enumerable properties.

The loop variable is a key, not the corresponding value. Use Object.hasOwn when you need only own keys. For ordinary own-object traversal, Object.entries is often clearer.

When to use it: Inspect object keys when enumeration behavior is intentional.

Example · independent snippet
const prices: Record<string, number> = { single: 1000, double: 1800 };
for (const key in prices) {
  if (Object.hasOwn(prices, key)) console.log(key, prices[key]);
}

Result explained: key becomes single and double; prices[key] gets the associated number.

Common mistake
Do not use for-in as an array-values loop. Array keys are strings and extra enumerable properties can appear.

for-of

Definition: for-of visits values produced by an iterable, such as an array, string, Set, or Map.

An iterable provides Symbol.iterator. You usually do not need to manage an index. for-of supports break, continue, and sequential await inside an async function. Plain objects are not automatically iterable.

When to use it: Process array values or stop when a match is found.

Example · independent snippet
const rooms = [101, 102, 103];
for (const room of rooms) {
  if (room === 102) break;
  console.log(room);
}
for (const [key, value] of Object.entries({ city: "Pune" })) {
  console.log(key, value);
}

Result explained: The first loop prints only 101; the second prints city and Pune.

Common mistake
for (const value of plainObject) fails unless the object implements iteration.

break and continue

Definition: break exits a loop. continue skips the rest of the current iteration and starts the next one.

Neither keyword exits a function. return exits the function, which also ends its loop. These keywords belong to the current loop or switch and cannot jump out of a callback into an outer loop.

When to use it: Stop at a match or ignore invalid items.

Example · independent snippet
for (const value of [0, 1, 2, 3]) {
  if (value === 0) continue;
  if (value === 3) break;
  console.log(value);
}

Result explained: The output is 1 and 2.

Common mistake
break inside forEach is invalid because forEach executes a separate callback function.

Try it yourself

Print the first three positive values from an array, skipping nonpositive values.

Show a possible solution 
let printed = 0;
for (const value of [-1, 0, 2, 4, 6, 8]) {
  if (value <= 0) continue;
  console.log(value);
  if (++printed === 3) break;
}

Array Methods Explained Individually
Array methods have different purposes and return values. A method’s name is not a substitute for understanding what it does.

forEach

Definition: forEach calls a callback once for each present array element and returns undefined.

Its callback receives value, index, and the array. Use it for side effects, such as logging. Returning from the callback does not return from the containing function or stop the whole traversal.

When to use it: Perform synchronous work for every element when no new array is needed.

Example · independent snippet
const rooms = [101, 102];
const result = rooms.forEach((room, index) => {
  console.log(index, room);
});
console.log(result);

Result explained: It logs index/value pairs 0/101 and 1/102. result is undefined.

Common mistake
forEach ignores returned promises; use Promise.all with map or an awaited for-of loop for async work.

map

Definition: map creates a new array containing each callback result.

It transforms values without inherently modifying the original array. The callback return type becomes the element type of the new array. If you forget return in a braced callback, the results are undefined.

When to use it: Convert prices to formatted labels or entities to DTOs.

Example · independent snippet
const prices = [100, 200];
const labels = prices.map(price => `₹${price}`);
console.log(labels);

Result explained: labels is string[] containing ₹100 and ₹200.

Common mistake
Using map only for side effects creates an unnecessary result array.

filter

Definition: filter creates a new array containing elements for which the callback returns a truthy result.

It selects existing values rather than transforming them. A type predicate can also narrow a union’s element type. The original array remains the same unless the callback mutates shared objects.

When to use it: Keep available rooms or valid records.

Example · independent snippet
const rooms = [{ id: 1, available: true }, { id: 2, available: false }];
const available = rooms.filter(room => room.available);

Result explained: available contains the first room object; that object is still shared with rooms.

Common mistake
filter returns an array, even if only one element matches.

reduce

Definition: reduce combines elements into one accumulator, which may be a number, object, array, or another value.

The callback receives the accumulator and current value. Its return becomes the next accumulator. An explicit initial value handles empty input and often makes TypeScript inference clearer.

When to use it: Calculate a total or group records.

Example · independent snippet
const total = [100, 200, 300].reduce((sum, price) => sum + price, 0);
const emptyTotal = ([] as number[]).reduce((sum, price) => sum + price, 0);

Result explained: The totals are 600 and 0.

Common mistake
reduce without an initial value throws on an empty array.

find and findIndex

Definition: find returns the first matching element or undefined. findIndex returns its index or -1.

Use find for a value and findIndex when you need its position. A match at index 0 is valid, while -1 means no match. Guard a find result before property access.

When to use it: Look up a room by ID.

Example · independent snippet
const rooms = [101, 102, 103];
console.log(rooms.find(room => room > 101));
console.log(rooms.findIndex(room => room === 101));

Result explained: The outputs are 102 and 0.

Common mistake
if (index) mishandles both 0 and -1; use index !== -1.

some and every

Definition: some answers whether at least one element passes. every answers whether all elements pass.

Both return booleans and stop once the answer is known. For an empty array, some returns false and every returns true.

When to use it: Check whether any room is available or all prices are valid.

Example · independent snippet
console.log([1, 2, 3].some(n => n > 2));
console.log([1, 2, 3].every(n => n > 0));

Result explained: Both results are true.

Common mistake
every([]) is true, so require a nonempty array separately if your business rule needs one.

includes and indexOf

Definition: includes tests for presence and returns a boolean. indexOf returns the first matching index or -1.

Use includes when you need only yes/no. Object values are matched by identity rather than by deep property equality. includes can find NaN while indexOf cannot.

When to use it: Check whether a role is allowed.

Example · independent snippet
const roles = ["admin", "viewer"];
console.log(roles.includes("admin"), roles.indexOf("viewer"));

Result explained: The outputs are true and 1.

Common mistake
includes({id:1}) does not match a different object with the same id.

slice and splice

Definition: slice copies a range without changing the original. splice removes or inserts elements in the original array.

slice(start, end) excludes end. splice(start, deleteCount, ...items) returns the removed elements. These have similar names but different mutation behavior.

When to use it: Use slice for pagination and splice for intentional editing.

Example · independent snippet
const values = [1, 2, 3, 4];
const page = values.slice(1, 3);
const removed = values.splice(1, 1, 99);
console.log(page, removed, values);

Result explained: page is [2,3], removed is [2], and values becomes [1,99,3,4].

Common mistake
splice mutates the array and returns removed items, not the updated whole array.

sort, reverse, toSorted, and toReversed

Definition: sort and reverse mutate an array. toSorted and toReversed return changed copies in compatible modern environments.

Default sort compares string forms. Supply a numeric comparator for numbers. Returning a negative comparator value places a before b; positive places b before a; zero keeps their relative ordering in a stable sort.

When to use it: Sort prices or display newest records first.

Example · independent snippet
const prices = [10, 2, 100];
const sorted = [...prices].sort((a, b) => a - b);
console.log(sorted, prices);

Result explained: sorted is [2,10,100]; prices remains [10,2,100].

Common mistake
Modern copying methods need matching runtime support and library declarations.

flat, flatMap, push, pop, shift, and unshift

Definition: flat removes nesting; flatMap maps then flattens one level. The other methods add or remove end/start elements in place.

push and unshift return the new length; pop and shift return the removed element or undefined. flat defaults to one level of flattening.

When to use it: Expand a list into pairs or maintain a small queue.

Example · independent snippet
console.log([1, 2].flatMap(n => [n, n * 10]));
const queue = [1, 2];
queue.push(3);
console.log(queue.shift());

Result explained: flatMap produces [1,10,2,20]. shift returns 1 and queue becomes [2,3].

Common mistake
Repeated shift or unshift can be costly on large arrays because many positions may need updating.

Try it yourself

From prices [200, 50, 500, 100], keep values at least 100, sort ascending, and calculate their total.

Show a possible solution 
const selected = [200, 50, 500, 100].filter(p => p >= 100).sort((a,b) => a-b);
const total = selected.reduce((sum,p) => sum+p,0); // 800

Strings, Numbers, Dates & RegExp
Learn standard-library operations used in almost every TypeScript application.

String methods and template literals

Definition: Strings are immutable text values. String methods return results rather than modifying the original string.

trim removes outer whitespace, toLowerCase changes case in a new string, includes searches a substring, split creates an array, and join combines array elements. Template literals interpolate expressions with ${...}.

When to use it: Normalize a search query or format a label.

Example · independent snippet
const query = "  ROOM  ";
const normalized = query.trim().toLowerCase();
const tags = "wifi,pool".split(",");
console.log(normalized, tags.join(" | "));

Result explained: The results are room and "wifi | pool". query still contains its original text.

Common mistake
String.length counts UTF-16 code units, which is not always the number of visible characters.

Numbers and Math

What is TypeScript?
TypeScript is a strongly typed superset of JavaScript developed by Microsoft. It compiles down to plain JavaScript and adds static type checking, making large codebases safer and more maintainable.

Why TypeScript?

Definition: Static type checking analyzes your code without executing it.

The compiler tracks which values are allowed at each position and checks that operations fit those values. This catches many mismatched arguments and missing properties. It cannot prove every business rule, validate network data, or prevent all runtime errors.

JavaScript is dynamically typed. TypeScript catches many type-related mistakes before execution, but runtime errors still need testing and validation.

❌ JavaScript example

  return a + b;
}

✅ TypeScript (type-safe)

  return a + b;
}
add(5, "10"); // ❌ Error caught instantly

Definition: Compilation translates TypeScript source into JavaScript; type checking analyzes its contracts.

Use a project-local TypeScript version so all contributors use the same checker. Run npx tsc -p . to read the project configuration. A transpiler can remove annotations without checking types, so a separate checking step may be needed.

The Any Type
any opts a variable out of type checking entirely — it accepts any value and allows any operation. It's a TypeScript escape hatch that defeats the purpose of using TypeScript.

any vs unknown vs never

Definition: any bypasses checking; unknown accepts values but requires evidence before use; never represents an impossible value.

Assign external data to unknown and narrow it before accessing properties. any allows nearly all operations, including invalid ones. never is useful for unreachable paths and exhaustive handling, rather than representing a normal empty value.

any — completely unchecked

anything = 5;
anything = "hello";
anything = true;
anything = [1, 2, 3];
anything.doWhatever(); // No error — dangerous!
anything.nonExistent.method(); // No error — runtime crash!
unknown — safe alternative to any 
let value: unknown = "hello";

// Must narrow before use
if (typeof value === "string") {
  console.log(value.toUpperCase()); // ✅ safe
}

// Without narrowing:
value.toUpperCase();
// ❌ Error: Object is of type 'unknown'

When any Spreads (Infectious)

Definition: An any-valued expression often causes related expressions to lose useful type information.

If a function accepts any and reads data.value, its return can also become any. Callers then lose checking for method access. noImplicitAny flags unintended implicit any, but does not prohibit explicitly written any.

any is contagious — avoid it 
function parse(data: any) {
  return data.value; // also any — spreads
}

const result = parse({ value: 42 });
result.nonExistent(); // ❌ No error shown! any propagated.
// Runtime crash only discovered in production
noImplicitAny in tsconfig (recommended) 
// tsconfig.json
{
  "compilerOptions": {
    "noImplicitAny": true  // flags implicit any when inference cannot supply a type
  }
}

// Now this throws a compile error:

  return x;
}

Classes & Access Modifiers

public

Accessible inside and outside the class; this is the default checked accessibility.

private

Accessible through the declaring class in TypeScript. Use # fields for JavaScript-enforced runtime privacy.

protected

Accessible within the class and derived classes, but not ordinary outside callers.

readonly

Allows initialization but prevents later checked reassignment through that property; nested objects may remain mutable.

constructor

Runs when new creates an instance and initializes its state.

Parameter property

A constructor parameter marked public/private/protected/readonly also declares and initializes an instance field.

static

Belongs to the class constructor, so call BankAccount.fromScratch rather than acc.fromScratch.

getter / setter

A getter computes a property on read; a setter handles assignment. Neither is a normal method call at the use site.

Definition: A class defines instance construction and shared behavior. Access modifiers control checked member access.

  private balance: number;
  protected accountNo: string;
  readonly createdAt: Date;

    owner: string,
    initialBalance: number

    this.owner = owner;
    this.balance = initialBalance;
    this.accountNo = `ACC-${id}`;
    this.createdAt = new Date();
  }

    if (amount <= 0) throw new Error("Amount must be positive");
    this.balance += amount;
  }

    return this.balance;
  }

    return `Balance: $${this.balance}`;
  }

  static fromScratch(owner: string): BankAccount {
    return new BankAccount(Date.now(), owner, 0);
  }

Type Narrowing
Narrowing refines a union type to a more specific type inside a conditional block. TypeScript tracks control flow to know exactly what type you're working with.

All Narrowing Techniques

typeof

Check primitive categories or function; object checks need an additional null guard.

instanceof

Check a real constructor’s prototype relationship, not an erased interface.

in

Check property presence, including inherited properties; optional properties complicate branches.

Discriminated union

Check a shared literal tag to identify an object variant.

Type predicate

A reusable boolean function declared with value is Type; its implementation must justify the claim.

Nullish check

Eliminate null/undefined explicitly without excluding valid zero or empty text.

Definition: Narrowing refines a broad type using runtime checks and control flow.

typeof identifies primitive categories, instanceof checks constructor/prototype relationships, in checks property presence, discriminant equality selects union variants, predicates encapsulate reusable checks, and nullish checks eliminate absence. 6 ways to narrow types 
// 1. typeof narrowing
function processValue(val: string | number) {
  if (typeof val === "string") {
    val.toUpperCase(); // string here
  } else {
    val.toFixed(2);    // number here
  }
}

// 2. instanceof narrowing
function handle(val: Date | string) {
  if (val instanceof Date) {
    val.toISOString(); // Date here
  }
}

// 3. in operator narrowing
type Fish = { swim: () => void };

Narrowing Techniques Explained
A narrowing check gives the compiler evidence for a more precise type along a code path.

typeof guards

Definition: typeof compares the runtime category of a value and can narrow a union.

It is useful for primitives and functions. Arrays and null need special care because typeof reports object. TypeScript follows control flow after the check.

When to use it: Separate a string-or-number parameter.

  return value.toUpperCase();
}

Result explained: Numbers are formatted with decimals; strings are uppercased.

Common mistake
typeof value === "object" does not prove the value is non-null.

Definition: instanceof checks a prototype relationship at runtime.

Use it with actual constructors such as Date or Error. It cannot check an interface because interfaces are erased. Objects from another realm can have different constructor identities.

When to use it: Distinguish a Date instance from a string.

Example · independent snippet

  if (value instanceof Date) return value.toISOString();
  return value;
}

Result explained: The Date branch has Date methods.

Common mistake
instanceof User cannot check an interface named User.

in guards

Definition: The in operator tests whether a property exists on an object or its prototype chain.

In a union, property presence can help identify a member. Optional properties may appear in both narrowed branches. Presence alone does not prove the property’s value is callable or of an expected runtime type.

When to use it: Distinguish object variants with different fields.

Result explained: Each branch calls a method supported by that variant.

Common mistake
in includes inherited properties; Object.hasOwn answers a different question.

Definition: Equality checks compare against specific values; truthiness checks eliminate some falsy possibilities.

Explicit equality with null or undefined is often safer when zero or empty strings are valid. A literal discriminant also lets the compiler select a union member.

When to use it: Preserve valid zero values and select exact states.

Example · independent snippet

  if (value !== undefined) console.log(value);
}

Result explained: Zero is printed correctly.

Common mistake
if (value) would skip zero.

Definition: A type predicate declares that a boolean-returning function verifies a particular type.

The syntax value is T connects a true result to narrowing. The compiler trusts the declared claim; you must implement adequate runtime checks. Use reusable guards on unknown values or array filters.

When to use it: Validate a simple primitive or object shape.

A predicate returning true without checking the shape can make unsound code appear safe.

Definition: A discriminated union gives each variant a shared property with a distinct literal value.

Definition: An iterable supplies Symbol.iterator. An iterator supplies next(), returning { value, done }.

When to use it: Accept arrays, sets, and generators through one contract.

  let total = 0;
  for (const value of values) total += value;
  return total;

Common mistake
An iterable and its iterator are related but not always the same object.

Definition: A generator function uses function* and yield to produce values incrementally.

Calling it returns a generator; its body advances as values are requested. Generator<Yield, Return, Next> describes yielded values, the final return, and values sent through next.

When to use it: Produce a lazy range without allocating every number first.

yield is not the same as return; return finishes the generator.

Structural typing normally lets two number aliases mix. A brand can distinguish RoomId from GuestId. A validated constructor/factory controls where branded values enter the program. The brand does not automatically exist at runtime.

When to use it: Prevent accidentally swapping domain IDs.

Example · independent snippet
declare const roomIdBrand: unique symbol;
type RoomId = number & { readonly [roomIdBrand]: "RoomId" };
function roomId(value: number): RoomId {
  if (!Number.isInteger(value) || value <= 0) throw new Error("Invalid room ID");
  return value as RoomId;
}
const id = roomId(201);

Result explained: id is branded after the factory validates its numeric rule.

A blanket as RoomId at every call site defeats the intended protection.

Ambient declarations and .d.ts

Definition: An ambient declaration describes a runtime value or module that exists elsewhere. A .d.ts file provides type information without implementing behavior.

declare function does not create a function. @types packages provide declarations for libraries that do not bundle them. Incorrect declarations can let broken code type-check.

When to use it: Describe an existing JavaScript library.

Result explained: The checker knows the signature, but execution requires the real library.

Common mistake
Adding declare merely to hide an error can cause a runtime ReferenceError.

Global versus module augmentation

Definition: Global augmentation adds to global declarations from a module. Module augmentation extends an existing imported module’s declarations.

Use export {} to establish a module for a globals.d.ts augmentation. Keep ambient declarations for a new external module separate from augmentation of an existing module. Declaration merging adds type members, not runtime properties.

When to use it: Describe a global configuration already installed by app startup.

// Runtime startup must still assign window.appVersion.

Result explained: Window now has an appVersion type property.

Declaring the property does not initialize it.

Namespaces and JavaScript modules solve different organization problems.

Definition: A decorator can inspect or customize supported class declarations or members through a decorator function.

Fetch, HTTP, JSON & Cancellation
Network APIs move untrusted data into your program. Validate status, content, and shape.

HTTP methods and responses

Definition: HTTP requests use methods such as GET for retrieval and POST for submission. A response includes a status, headers, and a body.

fetch returns a promise for a Response. A 404 or 500 usually fulfills that promise; inspect response.ok or status. response.json asynchronously parses JSON but does not validate its TypeScript shape.

When to use it: Read and write API data.

Example · independent snippet
async function load(): Promise<unknown> {
  const response = await fetch("/api/rooms");
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data: unknown = await response.json();
  return data;
}

Result explained: The function returns parsed data only after a successful HTTP response and successful parsing.

Common mistake
Network rejection, HTTP failure, invalid JSON, and invalid data shape are different failures.

JSON.stringify and JSON.parse

Definition: JSON.stringify serializes supported data as text. JSON.parse parses JSON text into JavaScript values.

JSON is a data format, not a TypeScript type system. Date objects normally serialize as strings. Undefined properties, functions, circular references, and bigint values have limitations or errors depending on their position and usage.

When to use it: Send a request body or persist simple data.

Example · independent snippet
const body = JSON.stringify({ roomId: 201, nights: 2 });
const parsed: unknown = JSON.parse(body);
console.log(body);

Result explained: body is JSON text. parsed still needs shape validation before trusted use.

Common mistake
JSON.parse does not restore class methods or automatically recreate Date instances.

Definition: AbortController creates a signal that cooperating APIs use to cancel work.

Pass signal into fetch, then call abort when the request is no longer needed. This can prevent stale UI work. Aborting does not necessarily undo a server action that already occurred.

When to use it: Cancel a previous search request.

Example · independent snippet
const controller = new AbortController();
const request = fetch("/api/rooms", { signal: controller.signal });
controller.abort();
request.catch(error => console.log("Request did not complete", error));

Result explained: The request typically rejects because its signal was aborted.

Common mistake
Cancellation is different from reversing a server-side change.

Definition: CORS is the browser’s cross-origin access mechanism controlled by server response headers.

If an API blocks access, a TypeScript annotation cannot fix it. Configure the server or a legitimate backend proxy. Do not put private API secrets in browser code.

When to use it: Diagnose a request that works server-side but fails in the browser.

Common mistake
mode: "no-cors" does not make the response readable; it usually produces an opaque response.

Event Listeners & Event Flow
An event announces that something happened. A listener is a function registered to respond to that event.

addEventListener

Definition: addEventListener registers a callback for a named event on an EventTarget, such as an element, document, or window.

Use target.addEventListener(type, handler, options). Pass the function itself; do not call it during registration. Multiple listeners can be registered for the same event. TypeScript often infers the event type from a known event name.

When to use it: Respond to user interaction without inline HTML handlers.

Example · independent snippet
// HTML: <button id="save">Save</button>
const button = document.querySelector<HTMLButtonElement>("#save");
button?.addEventListener("click", (event: MouseEvent) => {
  console.log("Save clicked", event.clientX);
});

Result explained: Clicking the button invokes the callback and logs the mouse position.

Common mistake
addEventListener("click", save()) calls save immediately. Use save or () => save().

target and currentTarget

Definition: target identifies the event’s originating target; currentTarget identifies the target whose listener is currently being invoked.

A click on a child icon can have that icon as target while the parent button is currentTarget. The types can be broad or nullable, so narrowing is needed. Prefer a known captured element when appropriate.

When to use it: Understand parent listeners and delegation.

Example · independent snippet
const container = document.querySelector("#rooms");
container?.addEventListener("click", event => {
  console.log(event.target, event.currentTarget);
});

Result explained: Clicking inside the container can produce two different elements.

Common mistake
event.target is EventTarget | null, not automatically HTMLElement.

Capturing and bubbling

Definition: Capturing carries an event toward its target; bubbling carries it outward through ancestors for events that bubble.

Register a capturing listener with { capture: true }. Ordinary listeners commonly use the bubbling phase. stopPropagation stops further propagation but does not cancel the browser’s default action. stopImmediatePropagation also prevents later listeners at that target.

When to use it: Coordinate nested interactive areas.

Example · independent snippet
document.addEventListener("click", () => console.log("capture"), { capture: true });
document.addEventListener("click", () => console.log("bubble"));

Result explained: For an ordinary click reaching document, its capturing listener runs before its bubbling listener.

Common mistake
Not every event bubbles. For example mouseenter and mouseleave do not.

preventDefault and listener options

Definition: preventDefault requests cancellation of a cancelable event’s default browser action. Listener options control capture, one-time use, passive behavior, and cancellation.

Use once for a listener that should run only once. A passive listener promises not to call preventDefault. A signal can remove a group of listeners when aborted. Default-action cancellation and propagation are separate concepts.

When to use it: Handle a form in JavaScript or clean up listeners.

Example · independent snippet
const controller = new AbortController();
window.addEventListener("resize", () => console.log("resized"), { signal: controller.signal });
controller.abort(); // removes this listener

Result explained: The resize listener is removed.

Common mistake
Calling preventDefault in a passive listener does not cancel the default action.

removeEventListener

Definition: removeEventListener unregisters a listener using the same event type, function identity, and matching capture setting.

A newly created arrow function is a different function even if its source text is identical. Keep a reference or use an AbortSignal for convenient cleanup.

When to use it: Avoid duplicate handlers when a view mounts and unmounts.

Example · independent snippet
function handleResize(): void { console.log("resize"); }
window.addEventListener("resize", handleResize);
window.removeEventListener("resize", handleResize);

Result explained: The listener is successfully removed.

Common mistake
removeEventListener("resize", () => ...) cannot remove a separately created arrow listener.

A semantic button can fire click through keyboard activation too, so click is useful for actions beyond a mouse-only design. Double-click handling may occur after individual clicks. Preventing a context menu should have a clear user need.

Result explained: Each matching interaction invokes its listener.

Common mistake
Do not make an essential action available only by double-click or right-click.

mousedown, mouseup, and mousemove

Definition: These mouse events report pressing a button, releasing it, and movement.

Use button to identify the changed button and buttons to inspect currently pressed buttons. clientX/clientY are viewport coordinates; pageX/pageY include page scrolling. Movement events can fire frequently.

When to use it: Understand custom mouse interaction or coordinate displays.

Example · independent snippet
document.addEventListener("mousemove", (event: MouseEvent) => {
  console.log(event.clientX, event.clientY);
});

Result explained: Coordinates change as the mouse moves.

Common mistake
Doing expensive work for every movement event can make the page slow.

mouseenter/leave versus mouseover/out

Definition: mouseenter and mouseleave detect entering or leaving a particular element without bubbling. mouseover and mouseout bubble and can occur when moving across child boundaries.

A move from a parent into its child can trigger over/out behavior even though the pointer remains inside the parent’s visual area. Choose the family that matches the interaction.

When to use it: Show an element-specific hover state or delegate a bubbling listener.

Example · independent snippet
const card = document.querySelector("#card");
card?.addEventListener("mouseenter", () => console.log("entered card"));
card?.addEventListener("mouseleave", () => console.log("left card"));

Result explained: The logs correspond to entering/leaving the card boundary.

Common mistake
Hover alone is not enough for a control that must work on touchscreens or keyboards.

Pointer events

Definition: Pointer events unify mouse, pen, and touch-like pointing input under PointerEvent.

pointerdown, pointermove, pointerup, and pointercancel describe a pointer lifecycle. pointerId identifies a pointer; pointerType identifies its kind. setPointerCapture keeps later events routed to an element during interaction.

When to use it: Build drawing or drag interactions that support multiple input devices.

Example · independent snippet
const area = document.querySelector<HTMLElement>("#area");
area?.addEventListener("pointerdown", (event: PointerEvent) => {
  area.setPointerCapture(event.pointerId);
  console.log(event.pointerType);
});
area?.addEventListener("pointercancel", () => console.log("interaction canceled"));

Result explained: The pointer is captured by the area after pointerdown.

Common mistake
A drag needs cleanup for pointercancel as well as pointerup, and may need an appropriate touch-action CSS value.

Touch and wheel events

Definition: Touch events describe contacts using touch lists. wheel describes scrolling-device deltas.

Pointer events are often a better first choice for unified pointing input. WheelEvent exposes deltaX, deltaY, and deltaMode, whose units need interpretation. Browser defaults and passive listeners affect cancellation.

When to use it: Inspect a gesture or wheel input when required.

Example · independent snippet
window.addEventListener("wheel", (event: WheelEvent) => {
  console.log(event.deltaY, event.deltaMode);
}, { passive: true });

Result explained: The listener observes deltas without blocking scrolling.

Common mistake
Wheel deltas are not always pixels. Do not prevent scrolling without a deliberate accessible interaction.

Definition: keydown occurs when a key is pressed; keyup occurs when it is released. KeyboardEvent exposes key, code, repeat, and modifier flags.

key describes the interpreted key; code identifies a physical key position. Repeated keydown events can occur while a key is held. keypress is deprecated and should not be the default choice.

When to use it: Handle Escape or deliberate keyboard shortcuts.

Example · independent snippet

  if (event.key === "Escape") console.log("Close dialog");
  if (event.ctrlKey && event.key.toLowerCase() === "s") {
    event.preventDefault();
    console.log("Save shortcut");
  }
});

Result explained: Escape triggers the close action; Ctrl+S triggers the save action.

Common mistake
Avoid hijacking typing shortcuts in inputs. Keyboard layout and platform modifier differences matter.

input, change, and beforeinput

Definition: input commonly fires as an editable value changes through user input. change fires when a change is committed. beforeinput occurs before certain editing changes.

For text input, input is usually appropriate for live search; change often waits for commitment such as losing focus. Programmatically setting .value generally does not automatically fire input or change. Not all editing actions can be canceled through beforeinput.

When to use it: Perform live validation or respond to a selected value.

Example · independent snippet

input?.addEventListener("change", () => console.log("committed", input.value));

Result explained: Typing triggers live updates; committing triggers change according to the control.

Common mistake
InputEvent is useful for editing details, but a known input element is often the simplest way to read .value.

focus, blur, focusin, and focusout

Definition: focus and blur report gaining or losing focus and do not bubble. focusin and focusout provide bubbling counterparts.

Focus is relevant to keyboard navigation and accessibility, not just mouse clicks. Use focus-visible CSS to indicate keyboard focus. A parent listener can use focusin for delegation.

When to use it: Show field help or validate when leaving a field.

Example · independent snippet
const input = document.querySelector<HTMLInputElement>("#email");

input?.addEventListener("blur", () => console.log("validate", input.value));

Result explained: The callbacks run when focus enters and leaves the input.

Common mistake
Removing visible focus styles can make keyboard navigation difficult.

submit, FormData, and reset

Definition: submit announces a form submission attempt. FormData collects successful named controls. reset returns controls to their defaults.

Listen on the form rather than only the submit button so keyboard submission is handled too. preventDefault avoids normal navigation when JavaScript handles the submission. Browser validation can prevent submit from firing for invalid controls.

When to use it: Read and validate a booking form.

Example · independent snippet
// HTML: <form id="booking"><input name="guest" required><button>Book</button></form>

form?.addEventListener("submit", (event: SubmitEvent) => {
  event.preventDefault();

  const guest = data.get("guest");

form?.addEventListener("reset", () => console.log("reset requested"));

Result explained: The listener reads the guest field without navigating away.

Common mistake
FormData.get returns a string, File, or null. A missing name attribute means a field is not collected.

Definition: Clipboard events report copy, cut, and paste. Composition events report text composition used by input methods.

compositionstart/update/end and InputEvent.isComposing help avoid submitting or filtering incomplete composed text. Clipboard access has permission and secure-context requirements depending on the API.

  console.log(event.clipboardData?.getData("text"));

Do not block paste on ordinary password or form fields without a strong reason.

Definition: scroll reports a change in scroll position; resize reports a resized window.

When to use it: Update a reading progress indicator or layout-dependent behavior.

When to use it: Pause animation or show an offline indication.

Event delegation

Definition: Delegation places one listener on an ancestor and uses the event target to identify the relevant child.

It works well with bubbling events and dynamically added elements. closest locates a matching ancestor of the clicked element. Guard that the result belongs to the intended container and check data attributes.

When to use it: Handle a changing list of room action buttons.

Example · independent snippet
// Container HTML includes buttons with data-room-id="201".
const list = document.querySelector<HTMLElement>("#rooms");
list?.addEventListener("click", event => {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest<HTMLButtonElement>("button[data-room-id]");
  if (!button || !list.contains(button)) return;
  const id = Number(button.dataset.roomId);
  if (Number.isFinite(id)) console.log("Selected room", id);
});

Result explained: Clicks on text or an icon inside an eligible button can still find the button.

Common mistake
Do not assume target itself is the button. Delegation needs a propagation path that reaches the listener.

CustomEvent and dispatchEvent

Definition: CustomEvent carries application-defined data in detail. dispatchEvent delivers an event through the target.

Set bubbles when ancestor listeners should receive it. TypeScript cannot automatically know every arbitrary custom event’s shape unless you add event-map declarations or an appropriately checked handler. dispatchEvent invokes listeners synchronously.

When to use it: Notify a widget that a booking was created.

Example · independent snippet
interface BookingDetail { id: number }
declare global {
  interface DocumentEventMap { "booking:created": CustomEvent<BookingDetail> }
}
export {};
document.addEventListener("booking:created", event => console.log(event.detail.id));
document.dispatchEvent(new CustomEvent<BookingDetail>("booking:created", { detail: { id: 101 } }));

Result explained: The listener logs 101 synchronously during dispatch. Run this as a module.

Common mistake
Custom event detail has no automatic runtime validation when another source dispatches the event.

Drag/drop uses dragstart, dragover, and drop; allowing drop commonly needs preventDefault in dragover. Media elements expose play, pause, ended, timeupdate, and error. Images expose load/error. CSS motion exposes transitionend and animationend. Workers and cross-window communication use message.

When to use it: Look up the event map and API contract when adding a specialized feature.

Common mistake

Definition: These browser APIs store string key/value pairs. localStorage commonly persists across sessions; sessionStorage is scoped to a page session.

Both are synchronous and can fail due to browser policy or quota. Use try/catch and treat parsed content as unknown. Stored data can be edited or become stale. Do not store secrets merely because storage is convenient.

When to use it: Remember a non-sensitive theme or learning preference.

Common mistake
TypeScript types do not protect data persisted by older versions or edited through browser tools.

When to use it: Display a guest name from a form or API.

Loops & Array Methods
TypeScript types loops and array methods fully — iteration variables, callbacks, and return values are all checked.

for-in Loop

Definition: for-in iterates enumerable string property keys from an object and its prototype chain.

The variable holds a key; object[key] reads the value. Use Object.hasOwn for own keys or Object.entries for convenient own key/value pairs. Avoid it for array values because indexes are strings and extra enumerable properties may appear.

Iterates over object keys (strings). Use for objects, not arrays.

for-in — object key iteration 
const user = { name: "Alice", age: 30, active: true };

for (const key in user) {
  // key: string (always)
  console.log(key);          // "name", "age", "active"
  console.log(user[key as keyof typeof user]); // typed access
}

// Typed object with Record
const scores: Record<string, number> = { alice: 95, bob: 87 };
for (const player in scores) {
  console.log(`${player}: ${scores[player]}`); // string, number
}
⚠️ Warning
Don't use for-in on arrays — it iterates over string indices AND prototype properties. Use for-of or forEach instead.

for-of & forEach

for-of

Iterates iterable values directly. Supports break/continue and awaited sequential processing.

forEach

Calls a function for each present array element. Returns undefined and does not await asynchronous callbacks.

Definition: for-of is a loop over iterable values. forEach is an array method that invokes a callback for each present element.

for-of supports break, continue, and sequential await. forEach returns undefined, does not support loop-breaking from inside its callback, and does not await callback promises. Its callback receives value, index, and array. Use forEach for synchronous side effects, map for a new array, and for-of when control over iteration matters.

for-of and forEach — value iteration 
const nums: number[] = [1, 2, 3, 4, 5];

// for-of — preferred for arrays
for (const num of nums) {
  // num: number (inferred from array type)
  console.log(num * 2);
}

// for-of with index using entries()
for (const [index, num] of nums.entries()) {
  // index: number, num: number
  console.log(`${index}: ${num}`);
}

// forEach — callback typed automatically
nums.forEach((num, index, array) => {
  // num: number, index: number, array: number[]
  console.log(`[${index}] = ${num}`);
});

// forEach on object array
const users: { name: string; age: number }[] = [
  { name: "Alice", age: 30 },
  { name: "Bob",   age: 25 },

JavaScript Migration, JSDoc & Project References
Adopt TypeScript incrementally and organize larger codebases without weakening every type.

allowJs, checkJs, and JSDoc

Definition: allowJs includes JavaScript files in a TypeScript project; checkJs requests checking for JavaScript. JSDoc comments can describe types in .js files.

You can start checking existing JavaScript before renaming files. Convert one boundary or module at a time and replace broad any values with precise contracts or unknown plus validation.

When to use it: Migrate an existing project gradually.

Example · independent snippet
// JavaScript file with checking enabled
/** @param {number} price @param {number} nights @returns {number} */
function total(price, nights) { return price * nights; }

Result explained: The checker uses the comment to understand the function contract.

Common mistake
Renaming .js to .ts does not automatically make all data safe.

Project references

Definition: Project references describe dependencies between separately built TypeScript projects.

They help organize larger repositories and enable coordinated incremental builds. Referenced buildable projects commonly use composite and declaration output. This is unnecessary overhead for a one-file learning exercise.

When to use it: Structure a shared library and dependent application.

Example · independent snippet
// app/tsconfig.json fragment
{ "references": [{ "path": "../shared" }] }
// Build related projects with: npx tsc -b

Result explained: The build can coordinate the shared project and app based on reference settings.

Common mistake
A path alias and a project reference are not the same feature.

JSX & Framework Integration
JSX is an optional syntax extension used by frameworks. It is not required for learning TypeScript itself.

JSX and TSX

Definition: JSX describes element-like expressions. TypeScript files containing JSX use the .tsx extension.

A framework supplies runtime behavior and JSX declarations. The jsx compiler option selects how JSX is transformed. Components, props, state, and framework event types depend on the chosen framework.

When to use it: Use TypeScript in a framework UI after mastering plain language and DOM fundamentals.

Example · independent snippet
// Framework-style concept, requiring its runtime and JSX types:
interface RoomProps { number: number; available: boolean }
// function RoomCard(props: RoomProps) {
//   return <article>Room {props.number}</article>;
// }

Result explained: The props contract checks callers. The commented component requires a configured framework project.

Common mistake
Native DOM events and a framework’s wrapped event types are not always interchangeable.

Keep contracts at boundaries

Definition: A framework integration connects language types to component, routing, state, and API boundaries.

Learn component props, nullable refs, event signatures, and API validation in the framework’s own documentation. TypeScript alone does not define all these conventions. Backend frameworks have their own request and response types too.

When to use it: Transfer TypeScript fundamentals to React, Vue, Angular, or a server framework.

Common mistake
A framework course and a language course overlap but are not identical scopes.

Projects: Apply What You Learned
Use progressively larger exercises to connect JavaScript behavior, TypeScript contracts, and boundary checks.

Project 1: Typed room catalog

Definition: A room catalog transforms, filters, and summarizes structured room records.

Model Room with id, name, price, and available fields. Implement a pure search/filter function, sort a copy by price, and calculate totals. Test empty lists and missing matches.

When to use it: Practice arrays, interfaces, functions, and optional results.

Example · independent snippet
interface Room { id: number; name: string; price: number; available: boolean }
function affordable(rooms: readonly Room[], max: number): Room[] {
  return rooms.filter(r => r.available && r.price <= max).sort((a,b) => a.price-b.price);
}

Result explained: The original array stays unchanged; the filtered result is sorted.

Common mistake
Mutating shared Room objects can still affect both arrays, even when the outer result is new.

Project 2: Booking form

Definition: A booking form gathers user input, validates it, and reports a structured result.

Use submit rather than only click; parse FormData values; validate integer nights and allowed room IDs; show messages with textContent. Add keyboard and focus behavior. Keep calculation separate from DOM work.

When to use it: Practice event types, narrowing, and validation.

Example · independent snippet
type Validation = { ok: true; nights: number } | { ok: false; error: string };
function validateNights(raw: unknown): Validation {
  if (typeof raw !== "string" || raw.trim() === "") return { ok: false, error: "Enter nights" };
  const nights = Number(raw);
  return Number.isInteger(nights) && nights > 0
    ? { ok: true, nights } : { ok: false, error: "Use a positive integer" };
}

Result explained: Only valid positive integer input produces the success variant.

Common mistake
Number("") is 0, so check required text before converting.

Project 3: API client and dashboard

Definition: An API client isolates network access and turns validated external data into trusted internal models.

Handle HTTP status, parsing, shape validation, cancellation, and UI loading/error states. Use a discriminated union for the UI state. Validate server input separately if you build the backend.

When to use it: Practice promises, modules, runtime guards, and reliable interfaces.

Example · independent snippet
type ViewState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

Result explained: Each state has only the fields valid for that state.

Common mistake
Client validation improves behavior but does not replace server validation or authorization.
